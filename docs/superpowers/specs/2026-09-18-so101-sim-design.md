# SO-101 MuJoCo sim on arrakis

Approved by dm1487 on 2026-09-18.

## Goal

Run the SO-101 arm in MuJoCo on arrakis, headless, as a base for either VLA fine-tuning or RL. The choice between those is still open, so this step builds only what both need.

There is no real arm on arrakis. The physical arm lives on host RobotLearning under `/home/dhruv/projects_dhruv/so101`, driven by the `so101` Claude session. Its notes informed the decisions below.

## Not in this step

- Rewards, success checks, episode termination.
- RL training or vectorized envs.
- Scripted demo generation or LeRobotDataset recording.
- VLA fine-tuning.
- Modeling the real arm's gravity sag. `so101` measured the real arm tracking about 8.8 mm below target, which it attributes to lerobot's P=16 servo gain. That only matters once a policy goes to hardware.

## Decisions

**Model.** Menagerie `robotstudio_so101` at commit `ac6b2b09983786f3036cab1000221017fa2193b4` (2026-05-18), vendored unmodified into `models/robotstudio_so101/`. This version has a `wrist_cam` and actuator gains derived for servo P=16. Do not use menagerie's `trs_so_arm100`, which is the older 5-DOF SO-100.

**No URDF, no placo.** IK runs in MuJoCo on the MJCF site `gripperframe`. The URDF's `gripper_frame_link` sits 19.9 mm from that site along x, and placo pins `pin==3.8.0` exactly. Using one model for both sim and IK avoids both.

> Correction, 2026-09-22. The axis above is wrong. `gripper_frame_link` is 19.9 mm along the site's **z**, the direction the jaws close, not its x. The `so101` session caught it, and a test inside this model settles it without needing the URDF: sweep `wrist_roll` a full turn and measure the radius the frame traces about the roll axis. The site traces 12.002 mm. An offset along x cannot change that, because x *is* the roll axis, and indeed ±19.9 mm along x still gives 12.002 mm. The real frame traces 7.899 mm, and 19.899 − 12.002 = 7.897. With the gripper vertical this is the difference between a purely vertical offset and a purely horizontal one. The magnitude was always right; only the axis was wrong.

**Base collision.** The MJCF `base` body has visual meshes only. The scene adds `so101`'s stand-in box, `size 0.045 0.045 0.040` at `pos 0.010 0 0.040`, with a contact exclude against `shoulder`.

**Stack.** Conda env `so101sim` at `/common/users/dm1487/envs/so101sim`: Python 3.10, mujoco 3.8.1, lerobot 0.4.4 with no extras. These match RobotLearning. lerobot goes in now so dependency clashes with mujoco show up before any data exists.

**Rendering.** `MUJOCO_GL=egl`. arrakis has no display.

## Components

`models/scene.xml` includes the vendored arm and adds a table, three cubes, a bin, a fixed front camera and the base collision box. Movable objects live in `models/objects.xml`, so changing the task edits one file.

`so101sim/units.py` converts between lerobot units and MJCF radians.
- Arm joints: degrees, zero at the model's zero.
- Gripper: 0 is closed, 100 is open, mapped linearly over the MJCF gripper joint range.
- A real-arm calibration offset would go here later.

`so101sim/ik.py` does damped least-squares IK, position only, on `gripperframe`, over the five arm joints. Position only because the arm has 5 DOF. The default seed is the zero pose, per `so101`'s finding that seeding from a folded pose gave 74.6 mm errors.

`so101sim/env.py` holds `SO101Env`, a Gymnasium env.
- Action: 6 joint targets in lerobot units, in lerobot joint order: `shoulder_pan shoulder_lift elbow_flex wrist_flex wrist_roll gripper`. Clipped to joint limits.
- Observation: a dict with `observation.state`, 6 floats in the same units as the action, and `observation.images.front` and `observation.images.wrist`, uint8 HxWx3.
- Control at 30 Hz, the rate lerobot uses. Physics timestep 1/300 s, so 10 substeps per control step.
- Reward is always 0 and episodes never terminate in this step.

`scripts/smoke.py` resets the env, runs a scripted motion over the cubes with IK, and writes an mp4 of both cameras side by side.

## MJX support

Added at dm1487's request after approval. The same `models/scene.xml` has to load into MJX and step on the GPU, so large-batch RL stays possible without a second model. The gym env stays on CPU MuJoCo, because MJX doesn't render cameras.

> Correction, 2026-09-25. MJX's Warp backend does render. mujoco 3.8.1 bundles MuJoCo Warp's batched ray-traced renderer, with RGB, depth and segmentation. It rendered this scene's front and wrist cameras at about 7,000 images/s at 128x128 over 1024 worlds. The gym env still runs on CPU MuJoCo, but by choice now: its EGL renderer draws shadows and lights the scene differently, so switching renderers changes every image a policy sees.

- `mujoco-mjx[warp]==3.8.1` and `jax[cuda12]` install as an optional `mjx` extra. jax 0.6.2 is the last
  release for Python 3.10, and it installs next to torch 2.10 without replacing any CUDA library.
- `so101sim/mjx.py` loads the scene and returns an MJX model plus data batched over N worlds.
- A test checks 4 batched worlds against CPU MuJoCo after 1 s of stepping: arm joints within 0.01 rad, and
  resting cube heights within 1 mm.
- An MJX RL env is not in this step.

**Backend: MuJoCo Warp, full contacts.** The plan was to trim contact pairs for MJX. Measurements on an RTX
6000 Ada at 1024 worlds changed that:

| Backend | Contacts | Step | Env-steps/s |
|---|---|---|---|
| JAX | full scene | 5.3 s for one world | unusable |
| JAX | finger pads, cubes, table, bin only | 240 ms | 4,263, and 41 GB of GPU memory |
| Warp | full scene | 33.6 ms | 30,490 |
| Warp | finger pads, cubes, table, bin only | 32.8 ms | 31,236 |

Warp with the full scene is 7x faster than JAX with trimmed contacts, and it keeps the same physics as the CPU
sim. So there's no trimming, and `mjx.py` pins `impl="warp"`. MJX defaults to JAX on GPU unless
`MJX_GPU_DEFAULT_WARP=true`.

Warp preallocates contact and constraint buffers. Too small a buffer prints `overflow` warnings and drops
contacts. At 32 constraint rows per world, resting cubes sink 2 mm. The defaults, 64 contacts and 256 rows per
world, match CPU.

## Tests

- Joint and actuator names come out in lerobot order.
- The unit conversion round-trips, and gripper 0 is the closed end.
- Held joint targets settle within 1 degree.
- IK reaches FK-generated points within 1 mm from the zero seed.
- Both cameras render frames that are not blank and differ from each other.
- Batched MJX worlds match CPU MuJoCo. Skipped when jax or warp isn't installed.

## Open questions

- The task. The session is named binpick, but nobody has confirmed bin picking.
- RL or VLA. This decides the next step: a reward plus vectorized envs, or a demo generator writing LeRobotDataset episodes.
- Top-down grasps probably need IK with an orientation term on the gripper axis. Position-only IK leaves the wrist free.
